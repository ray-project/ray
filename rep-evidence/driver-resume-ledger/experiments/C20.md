# Experiment: C20 (the C19 fix, verified)

**Pre-registered:** 2026-09-10, before the verification sweep was run. The fix
and its correctness argument were committed in [`C13.md`](C13.md) **before the
refutation was analysed and before a line of the fix was written**.

## Claim

> **C20.** With the carry-forward scanning epochs **ascending** (lowest first,
> highest readable wins) in addition to the C17 within-epoch ordering, N
> concurrent coordinator instances cannot cause the new epoch to lose committed
> progress.

## Refutes if

Any interleaving in which a unit acked by an instance holding the top epoch is
not recoverable after a higher epoch carries forward. Unchanged from C16 and
C19: the goalposts have not moved across three refutations.

## Setup, and what is deliberately harder this time

A fix that only works at the configuration that found the bug is not a fix, so
every axis is pushed past where the refutation appeared:

| axis | refutation ran at | this run |
|---|---|---|
| instances | 3 | **3 and 4** |
| window | 4, 5 | 4, 5, **6** |
| fuzz seeds | 3 | **5** |
| workloads | (4,1,2), (6,1,2) | both, unchanged |

Four instances is the interesting addition. Fidelity gap **F7** asserts that
three is enough to expose every cross-epoch class and that a fourth adds depth
rather than a new class. That assertion is **unvalidated**, and it is the same
assertion that "two is enough" turned out to be — which was wrong. So the
fourth instance is here to attack F7 directly, not to pad the sweep.

## Prediction (frozen)

1. **Zero `INV-DUR` at three instances**, all windows, all seeds. Confidence
   0.85 — the smoke test already showed 1,146 → 0 at `w = 5`.
2. **Zero `INV-DUR` at four instances.** Confidence **0.6**, and deliberately
   lower. The argument for the fix is inductive over epochs and should not care
   how many there are, but the same reasoning said two instances were
   representative and they were not. If a fourth instance produces violations,
   the ascending scan is *incomplete* rather than wrong, and the next question
   is which additional interleaving it misses.
3. `INV-FENCE-ACK` unchanged and still large — the fix does not address it.
4. NC15 (descending scan) red on `INV-DUR`; NC14 (shared id) red on `INV-ONE`.
5. The two-instance and sequential C6 sweeps stay clean.

## Thresholds

- **PASS:** zero `INV-DUR` at 3 *and* 4 instances, NC15 red, NC14 red, both
  regressions clean.
- **PARTIAL:** clean at 3, violations at 4 — record as `uncertain`, **not**
  proven, and open a claim for the missing case.
- **FAIL:** violations at 3.
- **VOID:** NC15 green.

## Negative controls

| control | mutation | expected |
|---|---|---|
| **NC15** `carry_forward_epochs_descending` | the pre-fix epoch scan order | `INV-DUR` RED |
| NC14 `same_id` | actor-derived instance id | `INV-ONE` RED |
| 2-instance + C6 regressions | unmodified | CLEAN |

## Result

- Run id: `runs/20260910-044309-C20`
- Outcome: **proven**

| prediction | outcome |
|---|---|
| (1) zero `INV-DUR` at 3 instances, all windows and seeds | **held** — 10,026 traces, zero |
| (2) zero `INV-DUR` at 4 instances (confidence deliberately only 0.6) | **held** — 13,582 traces, zero |
| (3) `INV-FENCE-ACK` unchanged and large | held |
| (4) NC15 red, NC14 red | held — NC15 1,146 `INV-DUR`; NC14 31 `INV-ONE` |
| (5) regressions clean | held — C6 sequential 7,620 traces clean, two-instance 4,950 clean |

**No surprise, which is itself worth noting.** This is the first experiment in
the loop whose result was exactly what the frozen prediction said, including the
one prediction that was deliberately hedged. Prediction (2) was given only 0.6
confidence *because* "two instances are representative" had already turned out
to be wrong; a fourth instance changed nothing, which is weak but real evidence
that the ascending-scan argument is inductive over epochs as claimed rather than
tuned to a particular count.

Fidelity gap **F7** ("three instances is enough") is therefore narrowed but not
closed: four behaves like three. It stays registered.

**Envelope.** Holds at 2, 3 and 4 concurrent instances, windows 4–6, unbounded
fuzz at 5 seeds, both workload shapes. Untested at 5+, and untested against a
stale tail longer than 8 operations (gap F6).
