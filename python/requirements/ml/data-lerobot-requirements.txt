# Kept out of data-test-requirements.txt, so they stay out of
# requirements_compiled.txt: that file constrains every depset, and lerobot's
# stack (diffusers, ...) conflicts with the release-test BYOD pins. Only the
# data CI depsets install these, with lerobot_overrides.txt.
#
# lerobot v3 datasource (ray.data.read_lerobot). lerobot >=0.5 requires
# Python >=3.12, so gate the whole stack -- including its torchcodec video
# decoder and the av writer the tests use -- behind that marker. The data
# locks compile for py3.10/3.11/3.12; only the 3.12 lock picks these up.
# Cap <0.6: lerobot 0.6.0's datasets/pyav_utils.py reads `av.option` at import
# time, which our pinned av (18.x) does not expose, so 0.6.0 fails to import
# against Ray's av. The 0.5.x line (what the datasource is built and tested
# against) decodes via torchcodec and imports cleanly.
lerobot>=0.5.0,<0.6; python_version >= "3.12" and python_version < "3.14"  # every lerobot caps numpy<2.3; no cp314 numpy below 2.3
# torchcodec's libtorchcodec is ABI-bound to a torch minor and declares no torch
# requirement in its metadata, so the line has to be pinned by hand: 0.10.x is
# built for torch 2.10 (0.9.x fails to load against it with a c10 ABI symbol
# error, and 0.11.x targets torch 2.11). lerobot 0.5.1 allows torchcodec>=0.3,<0.11.
torchcodec>=0.10,<0.11; python_version >= "3.12"
av; python_version >= "3.12"
