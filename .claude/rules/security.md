<!-- Security rules applying to all code -->
- Add token-based authentication to all new gRPC endpoints and RPC handlers to maintain Ray's security model
- Every new HTTP endpoint requires the token when auth is on, including metrics endpoints. Serve aiohttp apps behind `get_token_auth_middleware`, and metrics through `start_metrics_http_server`, `start_metrics_wsgi_server` or `get_token_auth_wsgi_app` (all in `python/ray/_private/authentication/http_token_authentication.py`). Add a path to a server's public (unauthenticated) path list only if, like the existing ones, it serves static assets, a health check, the auth mode or the login endpoint, and open metrics only with `RAY_AUTH_SKIP_METRICS=1`.
- Propagate auth tokens in new API calls (both C++ and Python sides) so that end-to-end authentication remains consistent
- Never put the auth token on a command line or subprocess argument, where `ps` and the dashboard show it, or in a log line, exception or error message. Hand a child process the path of an existing token file (`RAY_AUTH_TOKEN_PATH` or a file mount), or the name of the `RAY_AUTH_TOKEN` variable for it to read from its environment, and don't write a new copy of the token anywhere. The one exception is the mode-0600 `ray_prometheus.yml` that `ray metrics launch-prometheus` writes when `RAY_AUTH_TOKEN` is set.
- Code that connects to an existing cluster (a worker node, a driver, a `ray://` client, a CLI command or an SDK) never creates a token, since a token made there can't match the cluster's. Without a token it fails with the shared auth error. Only the existing creators make a token, all through `AuthenticationTokenLoader::CreateTokenIfMissing()`: a bare `ray.init()` that starts a new cluster, `ray.cluster_utils.Cluster()` and `AutoscalingCluster`, C++ and Java drivers that start their own cluster, `ray get-auth-token --generate`, and `ray up`. `ray start --head` never creates one.
- An auth rejection is final. Never retry it in a connect or reconnect loop, and raise it at once. In Python, code that catches `ConnectionError` to wrap, retry or swallow it must re-raise `AuthenticationError` (a `ConnectionError` subclass) unchanged. In C++, treat a `Status::IsUnauthenticated()` status or gRPC `UNAUTHENTICATED` as a terminal error, not a retryable one.
- Any new dashboard HTTP endpoint that echoes a `runtime_env` back must redact it for browser-originated requests. `runtime_env={"env_vars": {...}}` is the documented way users pass credentials to jobs, actors and tasks, so these payloads routinely carry cloud keys, DB passwords and API tokens. Never write `env_vars` values to log lines or process command lines either; the dashboard serves both.
- A new or changed Ray Data datasource that yields a `pa.Table` deserialized from external input (parquet, Arrow IPC, a service or library returning Arrow) without calling `raise_on_pickle_object_columns(table)` before yielding or materializing it is a remote code execution bug and should be avoided.
