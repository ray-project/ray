# rst-to-myst scripts

Scripts for the [`rst-to-myst`](../SKILL.md) skill. Run all three from the repo root, where `$SKILL` is `doc/.claude/skills/rst-to-myst`.

| Script | Purpose | How to run | Hardcoded paths |
|---|---|---|---|
| `rst2myst.py` | Faithful, format-only converter for the mechanical part of the skill's mapping. Writes the `.md` to stdout and one `FLAG` line to stderr per construct it can't translate, such as relative `.html` links, substitutions, RST tables, and autodoc. | From the repo root: `python3 $SKILL/scripts/rst2myst.py doc/source/<path>.rst > doc/source/<path>.md`. After editing it: `python3 $SKILL/scripts/rst2myst.py --selftest`. | None. |
| `render_diff.py` | Diffs a Read the Docs PR preview against `/en/master`, page by page, after normalizing host, release string, and the two inert MyST-versus-RST differences. | `python3 $SKILL/scripts/render_diff.py <preview_base_url> <page.html> [...]`. Requires `beautifulsoup4`. | Fetches `https://docs.ray.io/en/master/`. |
| `doctest_parity.py` | Proves a conversion keeps doctest coverage. Parses each converted `.md` and the `.rst` it replaced with Ray's `pytest-sphinx` parser, the same code the doctest targets run, and asserts identical sections and examples. It also runs pytest's stock doctest parser, which the macro's `--doctest-glob='*.md'` runs on every `.md`, and fails any closing fence it reads as expected output. `--census DIR` prints per-file example counts for a baseline. | From the repo root: `python3 $SKILL/scripts/doctest_parity.py <converted .md files>` (optionally `--base <ref>`), or `--census doc/source/<dir>`. After editing it: `python3 $SKILL/scripts/doctest_parity.py --selftest`. Requires `pytest` and `pytest-sphinx @ git+https://github.com/ray-project/pytest-sphinx`. | `--base` defaults to `upstream/master`. |

## Regression check for `rst2myst.py`

Beyond `--selftest`, the strongest check is to re-run the converter on the `.rst` sources of conversions that already shipped green, then diff its output against each PR's first commit, which is the pre-soft-wrap conversion. As of 2026-09-22 the reference set is the 31 `ray-core/` pages in ray-project/ray#66353, #66355, and #66377. The converter reproduces 28 of them exactly, ignoring runs of blank lines. The three differences are the two relative `.html` links it flags for hand translation, and one `2.` line the earlier hand conversion escaped unnecessarily, which renders the same.

The seven doctest pages in ray-project/ray#66380 extend the set to 38. The converter reproduces 4 of them exactly. `configure`, `miscellaneous`, and `starting-ray` differ in the relative `.html` links and the named reference it flags for hand translation. `configure` also differs in two constructs the PR's first commit got wrong and later commits fixed, which the converter now handles. Three cases were added to the converter from #66380. A named external target definition (`` .. _`Apache Arrow`: https://… ``) is now dropped with a flag, instead of becoming an HTML comment that the render diff surfaces. A prose line starting with `#` is now escaped, because CommonMark reads it as a heading. It broke that PR's first RtD build with a `myst.header` warning. Line blocks inside `{list-table}` cells are now converted and flagged. Before, they passed through unflagged and would have rendered literal `|` text.

The two table pages in ray-project/ray#66410 extend the set to 40. The converter reproduces `resource-isolation-with-cgroupv2` exactly. `cross-language` differs only in its two simple tables, which the converter passes through for hand conversion. Before #66410 it passed those two tables through with no flag at all, for two reasons. The table pattern matched only a table at column 0, and these sit indented under list items. The definition-list check also skipped any line inside a list. Both now flag. `--selftest` also checks flags now, through a `FLAG_CASES` list alongside the output cases. On a sweep of the remaining non-API `.rst` pages, the new flags newly catch the indented grid tables in `tune/tutorials/tune-scalability` and `ray-more-libs/ray-collective-custom-backend`. They also catch definition lists inside list items in `tune/examples/index`, `ray-more-libs/dask-on-ray`, and `ray-core/direct-transport/direct-transport`, plus `ray-core/miscellaneous`. That last one is the accidental definition list that #66380 found only in the render diff.

Batch 2's subtree PRs, ray-project/ray#66414, #66415, and #66417, converted 38 more pages, and their render diffs found seven constructs the converter got wrong without flagging. Each is now handled, and each has a `--selftest` case. Backslash escapes that RST processes survived as visible backslashes: inside default-role code (`` `task_id=\<task_id\>` ``), after it (`` ``ObjectRef``\s ``), and as escaped spaces (`(\ ``x``\ )`). Backticks inside bold became inline code, though RST shows them literally. Dash lines at a list item's text column became nested lists, though RST renders them inline, because the pseudo-list escape only checked lines under plain prose. A one-line term over an indented list, which is a definition list, had its dashes escaped instead. A comment holding Mermaid `-->` arrows ended its HTML comment early. A `testoutput` indented less than its list item's content pulled the item's `testcode` into a block quote with it. And a column-0 paragraph didn't reset the tracked list column, which hid two definition lists in `internals/metric-exporter` from the flag.

Re-running the converter over all 282 non-API `.rst` files on master changes the output of 23. One is `_templates/autosummary/class.rst`, a Jinja template that isn't a conversion target. Every other change is one of the fixes above, and the ones checked against `/en/master` match it. The batch-3 page `ray-core/handling-dependencies` gains two corrections, an inline `- Example` line and a `Note:` paragraph that the old output put in a block quote though it continues a list item. `data/transforming-data` stops escaping the bullets of a definition list, and several `train/` pages lose their `\s` escapes.

`ray-core/using-ray-with-jupyter`, ray-project/ray#66425, added one more case. An enumerator whose next line isn't indented is paragraph text in RST, even after a blank line, and the converter passed it through as a list start. It now escapes the marker and flags it. Re-running the converter over all 282 non-API `.rst` files on master changes the output of three, and all three match `/en/master`: `using-ray-with-jupyter`'s four numbered paragraphs, the two `1)` paragraphs in `cluster/vms/user-guides/community/spark`, and the "Global shuffle" paragraph in `data/shuffling-data`. That last page was hand-converted in ray-project/ray#66375 with the marker unescaped, so its preview renders an `<ol>` where `/en/master` renders one `<p>`.

Batch 3, ray-project/ray#66461, added four cases, and a `NOFLAG_CASES` list so `--selftest` can assert that a flag doesn't fire. An RST link with an embedded URI and no text, `` `<https://…>`_ ``, now converts to an autolink. Before, it passed through untranslated. The named-reference flag had caught it both times, but that flag printed the paragraph's first 80 characters rather than the reference, so its message read like a false positive. It now prints the reference. Text that MyST's `replacements` extension rewrites and docutils doesn't is now escaped, see Construct notes. A doctest directive with no blank line before its body is now flagged. The first sweep of the `replacements` escape over all 149 non-API `.rst` files on master turned up two over-reaches that the cases had missed: it escaped grid-table borders (`+---+`), and it escaped a `..` that opens leftover RST (`- .. image::`), hiding it from the residual check. Both have cases now. After the fixes, the converter's output changes for three files, and each change matches `/en/master`: `handling-dependencies`, `rllib/getting-started`, and the `(0..100)` ranges in `ray-observability/reference/system-metrics`. Reintroducing each of the five bugs fails `--selftest`.
